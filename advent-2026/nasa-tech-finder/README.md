# Day 08（12/8 火）NASAの特許から技術探し

- **アプリ名（フォルダ名）**：`nasa-tech-finder`
- **ジャンル**：宇宙
- **完成形**：Webアプリ＋API
- **組み合わせるデータ**：NASA技術移転API × NASA技術報告書（NTRS）
- **AI・技術の見どころ**：RAG

## 作るもの

課題を日本語で入れると、使えそうなNASAの特許と技術報告書を探し、仕組みをやさしく説明する

## 使い道

新規事業や研究のアイデア探し

## 確かめ方（評価）

人が作ったテスト用の課題20問で、上位に出た技術が本当に関係あるかを採点する

評価のスクリプトと結果は `eval/` に置く。

## 1日で作る工夫・注意

特許と報告書の要約部分だけを事前にベクトル化しておく

## 使い方

デモ：（公開後に記入）

### 画面

1. 「技術を探す」に課題を日本語で書いて「探す」（例のボタンもある）。20秒ほどで結果が出る
2. 「AI のまとめ」：使えそうな特許・報告書を AI が最大5件選び、「使えそうな理由」と「仕組み」をやさしく説明する。説明の数字は候補の説明文と照合した結果を ✓・⚠ で出す
3. 「近かった特許」「近かった技術報告書」：ベクトルの近さ（バー）の順の一覧。NASA のページへのリンクつき
4. 「API の使い方」タブ：コマンドと、画面が実際に受け取った応答
5. `?q=課題` で開くと、その課題で探す（同じ課題は保存した結果を返すので、回数を使わない）

### API

| | 内容 |
| --- | --- |
| `POST /api/search` | `{"problem": "寒い場所でも電池を長持ちさせたい"}`（5〜500字）。近い特許（上位8件）・報告書（上位6件）と、AI の説明。AI を使うので全体で1日10回・IP ごとに3回 |
| `GET /api/status` | 探せる特許の件数・分野ごとの件数・データを集めた日時 |

### 手元で動かす

```sh
cd advent-2026/nasa-tech-finder
pnpm vectors   # 特許を集めてベクトルにする（ベクトルがない特許だけ。初回は約15分）→ vectors/patents.json
pnpm index     # 特許の本文とベクトルを結びつける → server-data/index.json
pnpm dev       # http://localhost:5208
pnpm eval      # 課題20問の評価（約20分）。--reuse で保存した結果から表だけ作り直す
# 人の抜き取り確認：pnpm dev のあと http://localhost:5208/review.html（手元専用。0・1・2 のキーで判定し、eval/judgments.csv に保存）
```

## 必要な環境変数

- `VOYAGE_API_KEY`：特許と報告書のベクトル化（Voyage AI。デプロイのビルドでも使う）
- `ANTHROPIC_API_KEY`：課題の読み取りと説明（Claude）。`CLAUDE_MODEL` でモデルを切り替えられる
- Upstash Redis（公開デモでは必須）：回数の上限と結果の保存
- `VOYAGE_MODEL`（任意）：既定は `voyage-4`
- `NASA_API_KEY` は使わない（T2 と NTRS はキーなしで使える窓口がある。2026-11-26 に確認）

## 実装メモ

### 計画（2026-11-26）

**データ（下調べの結果）**

| データ | 取り方 | 量 |
| --- | --- | --- |
| NASA 技術移転（特許） | `https://technology.nasa.gov/api/api/patent/<語>`（キー不要）。全件を返す窓口はないので、15の分野名と一般的な語で検索して集め、重複を除く | 分野名だけで 541件（説明文は中央値 約1,000字） |
| NTRS（技術報告書） | `https://ntrs.nasa.gov/api/citations/search?q=`（キー不要）。題名・要約・公開区分・発行日 | 数十万件（「heat shield」だけで 1,064件）。全部を事前にベクトル化するのは重い |

**流れ（案）**

1. 事前準備（`scripts/`）：特許を集めて `data/` に保存し、題名＋説明文をベクトルにする
2. `POST /api/search`（課題の日本語）
   - Claude①：課題を、英語の「求めている機能」と検索語 3〜5個にする（Zod のスキーマで JSON に）
   - 特許：英語の「求めている機能」のベクトルと、事前に作った特許のベクトルの近さで上位を出す
   - 報告書：検索語で NTRS をその場で検索し（公開・要約ありのものだけ）、要約をベクトルにして近さで並べ直す
   - Claude②：上位の特許・報告書について、「なぜ課題に使えそうか」「仕組みをやさしく」を日本語で書く。挙げる ID は候補の中にあるものだけ（コードで照合）。数字も照合する
3. 画面：課題の入力欄、特許と報告書の一覧（NASA のページへのリンク）、AI の説明。日本語の UI
4. 評価：テスト用の課題 20問で、上位5件が課題に関係あるかを採点する（下の「決めること」）

### 決めたこと（2026-11-26、利用者と相談）

- ベクトル化は **Voyage AI**（`voyage-4`。多言語の検索向けで、日本語の課題から英語の特許を探せる）。キーは `VOYAGE_API_KEY`
- Voyage には**支払い方法を登録しない**（無料の制限：1分に3回・1万トークン）。そのため：
  - 特許のベクトルは手元で作って `vectors/patents.json`（約400KB）として Git に入れる。デプロイのビルドでは NASA から本文だけを集めて ID で結びつけ、Voyage は呼ばない
  - ベクトルにする文を短くする（特許は題名＋説明の先頭600字、報告書は題名＋要約の先頭400字）。報告書は検索語ごとに上位8件、合わせて最大40件だけ並べ直す
  - 混み合ったら API は「1分ほど待って」と 503 を返す

### 結果（[eval/RESULTS.md](eval/RESULTS.md)、課題19問＋関係する技術がない問題1問）

| 方法 | 上位5件のうち関係あり | 直接使えそう |
| --- | --- | --- |
| 特許：ベクトルの近さ | 59% | 21% |
| 特許：キーワード検索 | 41% | 11% |
| 報告書：並べ直したあと | 81% | 41% |
| 報告書：NTRS が返した順 | 72% | 35% |
| AI が選んだもの（平均 4.6件） | 87% | 62% |

採点は Claude。人の抜き取り確認はまだ。

### ハマったところ

- **特許の全件を返す窓口がない**：T2 の検索は語が要る。15の分野名だけだと 541件、一般的な語も足して55語で 616件。最後の20語ほどは1語あたり0〜2件しか増えなかったので、ほぼ全部とみなした
- **Voyage の無料の制限**：支払い方法を登録していないと「1分に3回・1万トークン」。特許616件のベクトル化（13回に分けて約15分）を手元で1回だけ行い、ベクトルを Git に入れた。検索のたびの報告書は最大40件・題名＋要約の先頭400字にして、1回の送信を1万トークンに収めた。8千トークンを21秒おきに送ると1分の上限を超えるので、間隔は送った量から決める
- **数字の照合が英語の数を読めなかった**：AI は「seventy-two hours」を「72時間」、「One hundred eighteen specimens」を「118個」と正しく訳していたのに、照合する側が数字しか読めず ⚠ を出した。英語の数と「minus 90」、範囲の「10-20」を読めるようにした

### 限界

- 特許は NASA の T2 ポータルに載っている 616件（ライセンスを受けられる技術）だけ。NASA の特許すべてではない
- 報告書は NTRS のキーワード検索の上位（検索語ごとに8件）から並べ直すので、検索語で拾えなかった報告書は出てこない（q03「がれきの下の人を探す」は報告書が 0/5）
- 関係する技術がない課題でも、AI は「参考になる程度」として何かを選ぶことがある（q20 ラーメン）。まとめで断ってはいる
- 評価の採点は Claude で、人の確認は抜き取りだけ
- 特許の技術を事業で使うには、NASA とのライセンス契約が要る
- 報告書は**その場で検索**：特許（616件）だけを事前にベクトル化し、報告書は課題ごとに NTRS を検索して上位の要約をその場でベクトル化して並べ直す
- 評価は **Claude が採点し、人が2割を抜き取りで確認**。課題20問は Claude が案を作り、利用者が確認・修正する（`eval/questions.json`）
- AI を使う検索は**全体で1日10回・IP ごとに3回**。同じ課題の結果は7日保存して使い回す
- 完成形が「Webアプリ＋API」なので、Day07 と同じく画面に「API の使い方」タブを置き、コマンドと実際の応答を出す

### AI の振る舞いで面白かった例

- 「寒い場所でも電池を長持ちさせたい」：特許には低温向けの電池がなく、AI は「特許の候補には低温を扱うものがなかったため、報告書を中心に選びました」と書いて、1960〜2000年代の低温電池の報告書を選んだ
- 英語の要約の「seventy-two hours」「One hundred eighteen specimens」を「72時間」「118個」と正しく訳した。照合する側が先に間違えた（⚠ を出した）のが面白い
- 「おいしいラーメンのスープを作りたい」：無理に技術を挙げず「直接使える技術はほとんどありません」と断りつつ、宇宙食のチキンヌードルスープの保存の報告書を「参考になる程度」として挙げた
