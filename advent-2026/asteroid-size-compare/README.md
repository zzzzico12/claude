# Day 09（12/9 水）地球に近づく小惑星を身近なサイズで

- **アプリ名（フォルダ名）**：`asteroid-size-compare`
- **ジャンル**：宇宙
- **完成形**：Webアプリ
- **組み合わせるデータ**：NASA JPL の接近天体データ × Wikidata
- **AI・技術の見どころ**：身近なものへの置き換え

## 作るもの

今月地球に近づく小惑星を、「東京タワー何本分」「月までの距離の何倍」のように身近なものに置き換えて、大きさと距離を図で見せる

## 使い道

「小惑星接近」のニュースを、怖がりすぎずに正しく理解する

## 確かめ方（評価）

比べる対象（建物の高さなど）はWikidataから取り、数字はすべてコードで計算して、AIの文章の数字と自動で照合する

評価のスクリプトと結果は `eval/` に置く。

## 1日で作る工夫・注意

小惑星の大きさは明るさからの推定で幅があるので「最小〜最大」で示す。NASAのデータは直前に動作を確認する

## 使い方

デモ：（公開後に記入）

### 画面

文章を減らし、図と大きな数字で見せる。

1. 上：これから30日に近づく小惑星のカード（大きさの目安のアイコン・日時・大きさ・月の何倍）。「近い順・大きい順・日時」で並べ替える
2. 中央：3D の比較（three.js）。小惑星（NASA のベンヌのモデルの形）と、比べる物（タイタニック・エッフェル塔・東京タワーなど8つ）と、身長 1.7 m の人を、**すべて実際の大きさ（1 単位 = 1 m）**で並べる
   - ドラッグで回転、ホイール・ピンチで拡大
   - スライダーで、推定の大きさの最小〜最大を動かす（直径が測られていれば固定）
   - ボタンで比べる物を切り替える（最初は大きさがいちばん近い物）
   - 「人の目線で見上げる」：人の目の高さ（1.6 m）から小惑星を見上げる
3. 右：大きな数字のタイル（大きさ・距離〈月の何倍と小さな図〉・速さ〈新幹線の何倍〉・地球にぶつかる？〈Sentry にもとづく〉）と、AI の説明（見出しは3D の上、全文は「くわしく読む」）
4. 右上の「English」で英語（日時は UTC）
5. URL：`?des=2011%20UE305&cmp=Q243&view=human` で、小惑星・比べる物（Wikidata の QID）・視点を選んだ状態で開ける

### API

| | 内容 |
| --- | --- |
| `GET /api/approaches` | 今日から30日・0.2 au 以内の接近と、コードで計算した大きさ・比べ方・距離・速さ・Sentry の情報 |
| `GET /api/explain?des=&time=&lang=` | 1件の「身近なものへの置き換え」の説明（AI）。小惑星・言語ごとに1回だけ作って保存し、全員で使い回す。全体で1日50回まで |

### 手元で動かす

```sh
cd advent-2026/asteroid-size-compare
pnpm dev       # http://localhost:5209
pnpm objects   # 比べる物を Wikidata から取り直す → reference/objects.ts
pnpm eval      # 評価（約20分。AI を約220回呼ぶ）。--reuse で保存した結果から表だけ作り直す
pnpm models    # 3D モデルを軽くする（1MB を超えるもの。--inspect で中身を見るだけ）
```

## 実装メモ

### 計画（2026-11-28）

**データ（下調べの結果）**

| データ | 取り方 | 中身 |
| --- | --- | --- |
| NASA JPL 接近天体データ（SBDB Close-Approach Data API） | `https://ssd-api.jpl.nasa.gov/cad.api?date-min=&date-max=&dist-max=&body=Earth&diameter=true&fullname=true`（キー不要） | 接近日時・距離（最小〜最大の幅つき、au）・相対速度・絶対等級 H・直径（測られていれば）。2026年12月・0.05 au 以内は13件で、直径が測られているものは0件 |
| Wikidata | SPARQL（`query.wikidata.org`） | 比べる物の高さ・長さ（P2048・P2043）。1つの物に値が複数あることがある（エッフェル塔は 300・324・330 m）ので、優先（preferred）の値だけを使う |

**大きさの推定（コードで計算）**：直径が測られていない小惑星は、絶対等級 H と反射率（アルベド 0.05〜0.25）から「最小〜最大」で出す。D[km] = 1329 / √p × 10^(−H/5)

**流れ（案）**

1. サーバーで JPL から今月の接近を取り、大きさの幅・月までの距離の何倍・速さを計算する
2. Wikidata から比べる物（建物・乗り物など）の大きさを取り、「東京タワー 約0.1〜0.3本分」のように計算する
3. AI：計算した比べ方の候補の中から、その小惑星に分かりやすいものを選んで短い説明を書く。数字はコードの計算と照合する
4. 画面：一覧と、選んだ小惑星の大きさ（比べる物と並べた図）・距離（地球と月との位置関係の図）

### 決めたこと（2026-11-28、利用者と相談）

- 比べる物は**日本と世界の有名な物**（Wikidata の値が1つに決まるものだけ。下の表）

- 画面は**日本語と英語**（Day06・Day07 と同じ切り替え）

**構成**

- `reference/objects.json`：比べる物を Wikidata から取ったもの（数KB、取得日つき。`pnpm objects` で取り直す）。Git に入れて、Wikidata が書き換わってもビルドが急に変わらないようにする

- `GET /api/explain`：1件の小惑星の「身近なものへの置き換え」の説明（AI）。数字はコードの計算と照合。言語ごとに1回だけ作って保存

- （2026-11-28 追記）画面を見たあとの相談：文章ばかりで読みにくいので、図と大きな数字を中心にする。大きさは three.js の3D で、公開されている3Dモデル（実際の建物の形）と並べ、回したり見上げたりできるようにする

### 結果（[eval/RESULTS.md](eval/RESULTS.md)）

| 確かめたこと | 結果 |
| --- | --- |
| AI の文章の数字がコードの計算と一致（日本語・英語 計218件） | 217 / 218（残る1件は、AI が「1.6本分」を「1.5倍ちょっと」と言い換えたもの。照合が正しく見つけた） |

| あおる言葉を使っていない | 218 / 218 |
| 明るさからの推定の幅に、測った直径が入る（332個） | 50%（反射率の幅を 0.03〜0.4 に広げると 81%、ただし幅は 2.2倍 → 3.7倍） |

### ハマったところ

- **英語の画面で AI が日本語を書いた**：返す形（Zod）の説明を日本語で書いていたため、英語の指示より説明の言語に引っ張られた。言語ごとに返す形を分けた
- **照合が「名前の中の数字」と「年の範囲」を数えていた**：2010 TH**19** の 19、「2087-2124」の -2124。名前は長い順に取り除き、範囲のハイフンはマイナスとして読まないようにした
- **確率を生のまま書いた**：AI が「約0.0015891889」「5.593e-8」と書いた。コードで「約0.16%（約630分の1）」に直して渡すようにした
- **大きさの推定の幅に、測った値が半分しか入らない**：反射率 0.05〜0.25 は小惑星の多くを含むはずだが、測られた332個では 50%。画面に「直径が測られた小惑星では、半分ほどがこの幅の外でした」と書いた
- **3D モデル**：person.glb の中身が FBX だった（FBX のまま読む）。タイタニックが 17.9MB（32万三角形）で、形を間引いて 3.1MB に。タイタニックのモデルに照明が入っていて、場面が真っ白に飛んだ（読み込むときに照明とカメラを取り除く）
- **人のモデル（FBX）が見えない・巨大な影が落ちる**：原因が3つ重なっていた。①骨格つきのモデルで、縮めても骨格の変形で元の大きさ（483 単位）のまま描かれた（読み込むときに、今の姿勢のまま動かない形に直す）。②直した形に元の巨大な外枠が残り、画面の外とみなされて描かれなかった（外枠を作り直す）。③材質の不透明度が 0（FBX の書き出しで透明度が逆に入った。不透明に直す）
- **「人の目線で見上げる」で見上げられない**：回す操作の部品が、カメラを見る点より下に行かせない設定だったため、カメラが小惑星の真ん中の高さまで押し上げられていた（見上げる視点だけ外す）。見上げる角度は 12° までにして、手前の人が画面に入るようにした
- **比べる物を切り替えるとラベルが重なる**：three.js の HTML のラベルは、親ごと場面から外しても画面に残る（切り替えのたびに消す）
- **最初に開いたとき3D が空**：一覧を描く前に、まだ用意していない関数を呼んでいた（`const` の関数を `function` に）

### 限界

- 大きさは明るさからの推定で、実際はこの幅の外のことも多い（上の結果）
- 3D の小惑星の形はベンヌのもので、実際の形は分からない（画面に書いた）
- 3D で比べられるのは、自由に使えるモデルが見つかった8つだけ
- 「怖がりすぎない一言」は Sentry の一覧にもとづく。Sentry に載っていないのは「これから100年、衝突の可能性が見つかっていない」という意味で、絶対にぶつからないという意味ではない

- 大きさは推定で、測られたものでは半分ほどが幅の外だったと正直に書く
- 3D の小惑星の形はベンヌのもの（実際の形ではない）
- 3D モデルのクレジット（CC BY）を記事にも書く
- Sentry に載っていない＝「これから100年、衝突の可能性が見つかっていない」で、「絶対にぶつからない」ではない
