## 使ったオープンデータ

| データ | 用途 | 提供元・ライセンス |
| --- | --- | --- |
| CelesTrak GP データ（stations・visual） | ISS・天宮・明るい衛星 約170機の軌道要素 | CelesTrak（無償公開。取得回数の制限あり） |
| Open-Meteo Forecast API | 1時間ごとの雲量の予報 | Open-Meteo（CC BY 4.0、**無料版は非商用**） |
| Open-Meteo Geocoding API | 地名 → 緯度経度 | 同上 |
| NASA Spot the Station（都市ごとの XML） | 答え合わせ（評価だけ） | NASA（パブリックドメイン） |

## 仕組み

```
GET /api/passes?place=札幌市
  ├─ 地名 → 緯度経度（Open-Meteo。30日保存）
  ├─ 軌道要素（CelesTrak。サーバーで2時間に1回だけ取得）
  ├─ 見える通過を探す（packages/orbit。ISS の7日分で数十ms）
  ├─ 各通過の時刻の雲量（Open-Meteo。場所ごとに1時間保存）
  └─ 見やすさの点数で順位を付ける

POST /api/ask {"question": "札幌で今週いちばん見やすいのは？"}
  ├─ Claude①：質問から「場所・日数・衛星」だけを取り出す（Zod のスキーマで JSON に）
  ├─ コード：上と同じ計算と順位付け
  └─ Claude②：順位の付いた一覧をもとに答えを書く → 数字を自動で照合
```

### 「見える」の3つの条件

NASA の Spot the Station と同じ考え方にしました。

1. 衛星が地平線から **10度以上**の高さにある
2. 観測地の空が暗い（太陽が地平線の **6度以上下**）
3. 衛星に**日が当たっている**（地球の影に入っていない）

ISS が夜空で光って見えるのは、地上は夜なのに、高いところにいる ISS にはまだ太陽の光が当たっているからです。3 の影は、地球の半径の円柱で近似しています。

### 通過の探し方

20秒刻みで高さを調べて、地平線（10度）の上にいる区間を見つけ、境目を二分法で0.5秒まで詰めます。その区間を1秒ごとに調べて「日が当たっていて、空が暗い」部分を取り出し、いちばん高いときは黄金分割で探します。ISS の14日分で約70msでした。

## 工夫したところ

### 主役は API。画面はそのデモ

前日の「人工衛星は今どこ？」は3Dの地球儀のアプリでした。今日は同じ軌道計算を、ほかの人が自分のアプリやスクリプトから呼べる部品（API）にしました。キーは不要で、ほかのサイトからも呼べます（CORS を許可）。

試せるページには「API の使い方」タブを置き、今の入力に合わせた `curl` のコマンドと、その画面で実際に受け取った応答をそのまま出しています。作り話のサンプルではないので、コマンドをコピーして実行すれば同じ形の JSON が返ります。

（スクリーンショット：API の使い方タブ）

### AI の役割を2つに絞った

時刻・方角・高さ・順位はすべてコードが決めます。AI がするのは、

- 質問から条件を取り出すこと（「今夜から3日間で、大阪から天宮は見える？」→ `{place: "大阪市", days: 3, satellite: "天宮"}`）
- 順位の付いた一覧を、読みやすい文章にすること

だけです。答えの中の数字（時刻・高さ・雲量・点数）は、渡した一覧と自動で照合し、合わないものには ⚠ を付けます。

### 見やすさの点数は、雲を掛け算にした

点数は「（高さの点80＋見える時間の点20）× (1 − 0.9 × 雲量)」です。はじめは足し算（高さ60＋雲量30＋時間10）にしていましたが、ロンドンで**雲量98%なのに真上を通る通過が1位**になりました。雲で見えなければ高さは関係ないので、掛け算にしました。

### 空の通り道を3Dのドームにした

観測地を中心にした半球の空を three.js で描き、選んだ通過の通り道を天球の上の線として描いて、衛星を30倍速で動かします。光る線が見える部分、点線は地球の影の中や低すぎて見えない部分です。ISS が地平線から昇ってきて、途中で光が消える（地球の影に入る）様子がそのまま見えます。

「見上げる」を押すと、観測地の真ん中から空を見上げる視点になり、頭上を衛星が横切ります。通り道の点列は API が `path=1` のときに返す（5秒ごとの方位角・高さと、見えるかどうか）ので、ほかの人が自分の画面で描くのにも使えます。

（スクリーンショット：外から見たドームと、見上げた視点）

## ハマったところ

- **Spot the Station の RSS がなくなっていた**：昔の都市ごとの RSS は 404 でした。data.nasa.gov のカタログをたどると、Day06 で使った ISS の軌道データと同じ NASA の S3 に、都市ごとの XML がありました（都市の緯度経度は入っていないので、Open-Meteo の地名検索で引きました）
- **「東京」が見つからない**：Open-Meteo の地名検索は「東京」では見つからず、「東京都」「Tokyo」なら見つかります。見つからなければ「市・都・府・県」を足して試すようにしました
- **真上に近い通過の方角が揺れる**：高さ85度の通過で、いちばん高いときの方角が、計算するたびに南南西になったり南西になったりしました。真上の近くでは1秒で方位角が大きく変わるので、いちばん高い時刻が1秒未満ずれるだけで変わります。最初は「AI が方角を言い間違えた」と思いましたが、AI に渡した値を確かめると合っていました

## どれくらいうまくいったか

NASA Spot the Station の予測と、日本10都市・世界7都市で比べました（`eval/RESULTS.md`）。

| 項目 | 結果 |
| --- | --- |
| NASA の通過のうち、こちらでも見つかった | **188 / 189（99%）** |
| 見え始めの時刻が同じ分 | **95%**（±1分以内 99%） |
| 最大の高さの差 | 中央値 0 度（±2度以内 96%） |
| 現れる方角が16方位で一致 | 99% |
| 消える方角が16方位で一致 | 93%（隣の方位まで含めると 100%） |
| 軌道要素から14日後でも | 見え始めのずれの中央値 10〜21 秒 |

こちらにだけある通過が9つありました。うち8つは、通過の途中で空が暗くなる（または明るくなる）もので、太陽の高さがちょうど −6 度のところで区切られていました。NASA はこういう通過を載せないことが多いようです。

AI の答えは、試した3つの質問で、数字がすべて計算結果と一致しました。
