## 今日作ったもの

依存ファイル（`package-lock.json` / `requirements.txt`）を渡すと、脆弱性を**「今日対応すべき順」**に並べたレポートを作る CLI と GitHub Action です。

（スクリーンショット：Job Summary に出たレポート）

古い Django のプロジェクトで試すと、脆弱性は136件ありました。そのうち今日対応すべきなのは10件で、実際に悪用が確認済みのものは1件（Pillow が同梱する libwebp の CVE-2023-4863）でした。

- 順位の根拠（悪用確認済みか、悪用される確率、深刻度、修正版）を表で出す
- AI が「なぜこの順番か」を説明する
- 放置・非推奨の依存には、AI が乗り換え先を調べて提案する（標準機能で足りる場合はそう答える）
- パッケージごとに「どこまで上げれば何件直るか」をまとめる

## 使ったオープンデータ

| データ | 用途 | 提供元・ライセンス |
| --- | --- | --- |
| [OSV](https://osv.dev/) | パッケージとバージョンから脆弱性を探す | Google / OpenSSF。元データベースごと（GitHub Advisory Database などは CC BY 4.0） |
| [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) | 実際に悪用が確認された脆弱性の一覧 | CISA・CC0 1.0 |
| [EPSS](https://www.first.org/epss/) | 30日以内に悪用される確率 | FIRST・無料（出典の明記が求められている） |
| [deps.dev](https://deps.dev/) | 最新版の公開日、非推奨の印 | Google Open Source Insights |

4つともキー不要です。

## 仕組み

```
依存ファイル → OSV（脆弱性）→ KEV・EPSS（悪用）→ コードで順位 → AI が説明・乗り換え先を調べる → コードで照合 → Markdown
```

優先度の式（コード）：

- KEV に載っていれば最優先
- それ以外は「EPSS × 深刻度の係数 × 依存の文脈」（開発用の依存は半分、npm の間接の依存は0.8倍）

AI（Claude Sonnet 5.5）の役割は2つだけです。

1. 上位の脆弱性について、コードが出した根拠だけを使って「なぜこの順番か」を説明する
2. 放置・非推奨の依存の乗り換え先を探す。AI に deps.dev を調べる道具を渡し、候補が実在して更新されているかを確かめさせる（エージェント）。提案されたパッケージは、最後にコードでもう一度確かめる

## 工夫したところ

### 1. 深刻度ではなく「悪用されそうか」で並べる

Dependabot や `npm audit` は深刻度（CVSS）で警告を出します。でも HIGH や CRITICAL は大量にあり、実際に悪用されるのはその一部です。CISA KEV（悪用確認済み）と EPSS（悪用される確率）を使って並べ直しました。

### 2. AI の提案を、AI にもコードにも確かめさせる

（エージェントの道具の定義と、✅ / ❓ の確認のコード）

### 3. 「非推奨」を2種類に分ける

（axios 0.21.0 と request の例）

## ハマったところ

- 同じ脆弱性が GHSA と PYSEC の2件で返ってきて、件数が245件に水増しされていた（まとめると136件）
- EPSS 0.99999 が「100.0%」と表示される
- ライセンスを記憶で書いたら間違っていた（OSV は元データベースごと、deps.dev は明記なし）

## どれくらいうまくいったか

**時点を戻して**確かめました。2022年6月から3か月ごとに、その日の EPSS と深刻度だけで、オープンソースの CVE（1回あたり約1.5万件）に順位を付けます。その後90日以内に KEV に載った脆弱性（のべ40件）を、何位に置けていたかを見ました。

| 並べ方 | 正解の順位（中央値） | 上位100件で拾えた数 |
| --- | --- | --- |
| 深刻度（CVSS）だけ | 1,931 位 | 1 / 40 |
| EPSS だけ | 254 位 | 11 / 40 |
| **このアプリ** | **140 位** | **13 / 40** |

深刻度で並べると、その後悪用された脆弱性は約1,900位に埋もれます。このアプリの並べ方では140位前後まで上がりました。

限界：

- EPSS だけでもかなり強く、このアプリとの差は小さい
- 公開されてすぐ悪用された新しい脆弱性（ray、litellm など）は、EPSS が付く前なので拾えなかった
- 依存の文脈（開発用かなど）の効果は、この評価では測れない

（詳細は `eval/RESULTS.md`）
