# Day 04（12/4 金）名画のエディタ配色

- **アプリ名（フォルダ名）**：`masterpiece-vscode-theme`
- **ジャンル**：名画
- **完成形**：VS Code拡張
- **組み合わせるデータ**：シカゴ美術館 × Open-Meteo（メトロポリタン美術館は画像を取得できなかったので使っていない。実装メモ参照）
- **AI・技術の見どころ**：画像からの配色抽出、VS Code拡張

## 作るもの

好きな名画を選ぶと、その絵の色からVS Codeのテーマを作る。文字の読みやすさ（コントラスト）は自動で調整し、天気や時間帯で絵が切り替わる

## 使い道

毎日見るエディタを、自分だけの絵の色にする。VS Code拡張として公開する

## どんな効果があるか

- **毎日見るエディタが、好きな名画の色になる**：絵から取り出した色だけで作った配色（17点分）。雨の日はカイユボット、夜はホイッスラー、雪の日はモネの積みわら…と、天気と時間帯に合わせて絵が替わる（オンにした場合）
- **きれいなだけでなく、読みやすさを保証**：絵の色そのままでは、コードの色の半分が読みやすさの基準（WCAG AA、コントラスト比 4.5:1）を満たしていなかった。すべての文字の色を、絵の色合いを保ったまま明るさだけ調整して、17テーマ・272組すべてで基準を満たした
- **絵を知るきっかけになる**：ステータスバーの絵の名前を押すと、作品の画像と解説、なぜこの配色にしたかが出る

## 確かめ方（評価）

すべての文字色が、読みやすさの基準（WCAGのコントラスト比）を満たすかを自動で検査する

評価のスクリプトと結果は `eval/` に置く。

## 1日で作る工夫・注意

配色の抽出は色のクラスタリングで行い、AIは「どの色を背景・キーワード・コメントに割り当てるか」の判断と絵の解説を担当する

## 必要な環境変数

- 拡張機能を使うだけなら：なし（AI は拡張機能の中では動かない）
- テーマを作り直すとき（`pnpm themes`）：`ANTHROPIC_API_KEY`・`CLAUDE_MODEL`

## 使い方

### インストール（いまは .vsix ファイルから）

```bash
cd advent-2026
pnpm install && pnpm build            # 最初の1回だけ
cd masterpiece-vscode-theme
pnpm package                          # dist/masterpiece-theme.vsix ができる
code --install-extension dist/masterpiece-theme.vsix
```

VS Code の拡張機能の画面の「…」→「VSIX からのインストール…」でも入れられる。

### 使う

1. コマンドパレット（`Cmd+Shift+P` / `Ctrl+Shift+P`）で **「名画テーマ: 絵を選ぶ」** → 好きな絵を選ぶ（「基本設定: 配色テーマ」の一覧の「名画: …」からでもよい）
2. 天気と時間で切り替えるなら **「名画テーマ: 天気と時間で自動で切り替える」**。設定の `masterpieceTheme.latitude` / `longitude` に場所を入れる（既定は東京）
3. エクスプローラーの下の **「名画」パネル**に、いまの絵と、そこから取った色の帯がいつも表示される（ドラッグで右側のサイドバーにも移せる。閉じたら「名画テーマ: 絵をサイドバーに表示」）
4. パネルの絵かステータスバー右の絵の名前（または **「名画テーマ: いまの絵について」**）で、絵の画像・解説・配色を表示

エディタの背景に絵を敷く公式の方法は VS Code にない（配色テーマは色しか指定できない）。VS Code 本体の CSS を書き換える方法はあるが、「インストールが壊れている」という警告が出て、更新のたびに元に戻るので使わない。絵は横のパネルに表示する。

| コマンド | 内容 |
| --- | --- |
| 名画テーマ: 絵を選ぶ | 17点の一覧から選ぶ（ダーク／ライトと雰囲気つき） |
| 名画テーマ: いまの絵について | 画像・解説・配色の意図・調整した色 |
| 名画テーマ: 絵をサイドバーに表示 | 「名画」パネルを開く |
| 名画テーマ: 天気と時間で自動で切り替える | オンにして、すぐ切り替える |
| 名画テーマ: いまの天気で選び直す | 天気を取り直す |
| 名画テーマ: 自動の切り替えを止める | オフにする |

### 使用例

- **雨の日の昼**：「雨」の絵 → カイユボット「パリの通り、雨の日」（ライト）
- **晴れの夜**：「夜」の絵 → ホイッスラー「夜想曲」かムンク「窓辺の少女」（ダーク、日替わり）
- **雪の日**：モネ「積みわら（雪の効果、曇り空）」かトワクトマン「氷に閉ざされて」など
- **夕方（日の入りの前後）**：モネの積みわら（日没）など

天気と時間帯の決め方（[lib/paintings.ts](lib/paintings.ts)）：嵐（雷雨・風速40km/h以上）→ 雪 → 雨 → 朝（日の出の30分前〜90分後）→ 夕方（日の入りの90分前〜30分後）→ 夜 → くもり → 晴れ の順。その雰囲気の絵がなければ近い雰囲気の絵を使う。

### テーマを作り直す

```bash
pnpm themes            # AI で色の割り当てと解説を作り直す（17回呼ぶ。Sonnet 5.5 で約50〜80円）
pnpm themes:rebuild    # AI を呼ばずに、保存済みの割り当てからテーマだけ作り直す（lib/theme.ts を変えたとき）
pnpm eval              # 評価（eval/RESULTS.md）
```

## 実装メモ

### 作り（設計）

- **完成形**：VS Code 拡張機能（`.vsix`）。テーマは**事前に作って同梱**し、拡張機能の中では AI を呼ばない（利用者にキーや料金の負担をかけない）
- **テーマの作り方**（`scripts/build-themes.ts`、事前に1回）
  1. シカゴ美術館のパブリックドメインの絵を17点選ぶ（晴れ・雨・雪・夜・夕方などの雰囲気がばらけるように）
  2. 幅400pxの画像から代表色を取り出す：面積の多い12色（k-means、OKLab の空間）＋小さく鮮やかな色4色まで
  3. Claude（Sonnet 5.5）に画像とパレットを見せ、背景・文字・キーワード・文字列・関数・型・数値・コメント・アクセントの色をパレットから選ばせ、ダークかライトか、絵の解説、配色の意図、雰囲気（晴れ・雨・夜など）を書かせる
  4. コードで：AI の選んだ色をパレットの色にそろえる → 背景をダークなら十分暗く・ライトなら十分明るく → 文字の色を WCAG AA（4.5:1）まで明るさだけ調整 → コードの色どうしを ΔE2000 で 8 以上離す → VS Code のテーマの JSON を書き出す
- **拡張機能**（`src/extension.ts`）：Open-Meteo の天気（天気コード・風速・昼か夜か・日の出と日の入り）から雰囲気を決め、合う絵のテーマに切り替える。いまの絵をエクスプローラーの「名画」パネル（Webview ビュー）にいつも表示し、解説を Webview で表示する
- **共通部品**：美術館のデータの取得を `packages/museum-data` に作った（Day13・14・19 でも使う）

### 試してわかったこと・実装してわかったこと（2026-11-23）

- **メトロポリタン美術館の画像は、プログラムから取得できない**：画像サーバー（images.metmuseum.org）がボット確認のページを返す。作品データの API は使える。ブラウザのふりをして回避することはしない（Claude Code の安全確認でも止められた）。Day04 はシカゴ美術館だけで作った。`packages/museum-data` には Met のデータ取得だけを入れた
- **シカゴ美術館の画像は、案内どおりに名乗れば取れる**：`AIC-User-Agent` ヘッダーにアプリ名を入れる
- **面積の多い色だけでは、絵を特徴づける色が消える**：面積の多い12色だけだと、スーラの服の赤のような小さく鮮やかな色が入らない。彩度の高い上位3%の画素から、別に4色まで取り出すようにした（最初は明るさと彩度だけで似た色を除いていて、色相の違う赤まで除いてしまった。色相も含めた距離に直した）
- **コントラストだけを満たすと、コードの色がみんな同じになる**：ホイッスラーの「夜想曲」はほぼ灰緑の一色で、基準を満たすまで明るさを上げると、キーワード・文字列・型・コメントがほぼ同じ色（`#84887c`）になった。「コードの色どうしは ΔE2000 で 8 以上離す」規則を足した。背景から遠ざける方向に明るさを動かすので、コントラストは下がらない。ただし一色の絵では限界がある（元の画像に鮮やかな色がほとんどない）
- **`pnpm rebuild` は pnpm 自体のコマンド**：AI を呼ばずにテーマを作り直すスクリプトを `rebuild` と名付けたら、パッケージの再ビルドが走って何も起きなかった。`themes:rebuild` に改名
- AI は、指示どおりパレットの色だけを選び（パレット外は0件）、解説に数字を書かなかった（照合で0件）
- 1回の作成：17点で約1分45秒
- **色だけでは、どの絵のテーマか分かりにくい**（試してもらった感想）：エディタの背景に絵を敷くことは VS Code の公式の機能ではできないので、エクスプローラーに絵と色の帯をいつも表示するパネルを足した（v0.2.0）
- **パネルに絵が表示されなかった**：Webview の `<img>` からシカゴ美術館の画像サーバーを直接読むと、名乗るためのヘッダー（`AIC-User-Agent`）を付けられず、ボット確認のページが返る。絵の画像（幅400px、17点で約830KB、パブリックドメイン）を拡張機能に同梱して、手元のファイルから表示するようにした（v0.2.1）。通信も要らなくなった

### 評価の結果（2026-11-23）

詳細は [eval/RESULTS.md](eval/RESULTS.md)。17テーマ × 16組＝272組。

| 割り当て | AA（4.5:1）を満たした組 | AAA（7:1） | 調整前に AA を満たしていたコードの色 | 調整による色の変化（ΔE2000） | コードの色どうしの最小の差（ΔE2000） |
| --- | --- | --- | --- | --- | --- |
| **AI（Claude）** | **272/272（100%）** | 29% | 50% | **8.6** | **7.0** |
| 機械的な割り当て（明るさ・彩度の順） | 272/272（100%） | 28% | 42% | 11.5 | 6.5 |

- 読みやすさの基準は、調整によってすべて満たす（どちらの割り当てでも）
- **AI の割り当ては、調整で色を変える量が少ない**（ΔE 8.6 対 11.5）＝絵の色をより多くそのまま使えている。見分けやすさも少し良い
- 一色に近い絵（ホイッスラー）は、コードの色どうしの差がほとんどつけられない

### 一言でいうと

名画の色から VS Code のテーマを作る拡張機能。色を取り出すのは k-means、どの色をどこに使うかは AI が絵を見て決め、読みやすさ（WCAG AA）はコードが保証する。天気と時間帯で絵が替わる。AI は事前に一度だけ使い、拡張機能の中では動かない。

### AI の振る舞いで面白かった例

- カイユボットの配色の意図：「雨に濡れた石畳の灰色と、淡いベージュの空を背景にして、深い紺色の文字で読みやすくしました。街灯の深い緑をアクセントにし、服や建物のくすんだ赤茶を文字列の色に使いました」
- 暗い絵はダーク、明るい絵（北斎・広重・カイユボット）はライトと、絵に合わせて選んだ（17点中、ダーク8・ライト9）
- 雰囲気の付け方：北斎「神奈川沖浪裏」は嵐、ホイッスラー「夜想曲」は夜・夕方・くもり、モネの積みわらは連作ごとに夕方・雪・晴れを付け分けた

### ハマったところ（記事向けの言い方）

0. 色だけのテーマは「どの絵か分かりにくい」と言われた。エディタの背景に画像を敷く公式の方法はないので、絵を横のパネルに出すことにした
1. メトロポリタン美術館の画像サーバーがボット確認を返し、プログラムから画像を取れなかった（データの API は使える）
2. 面積の多い色だけだと、絵の「差し色」が消える
2.5 パネルの `<img>` から美術館の画像を読むと、ボット確認で表示されなかった → 画像を同梱
3. 読みやすさだけ満たすと、灰色の絵ではコードの色が全部同じになった
4. `pnpm rebuild` という名前のスクリプトが、pnpm 自体のコマンドに負けて動かなかった

### 正直に書いておくこと（限界）

- WCAG は「読みやすさの最低限」で、目の疲れにくさや好みまでは保証しない
- 一色に近い絵（ホイッスラー）では、コードの色の見分けやすさに限界がある
- 「きれいか」「絵らしいか」は数字で測っていない（スクリーンショットで判断してもらう）
- メトロポリタン美術館は使えなかった（仕様では使う予定だった）
- 天気の判定は Open-Meteo の天気コードの大まかな分類。地域の細かい天気までは反映しない
- テーマは17点に固定。利用者が好きな絵からテーマを作る機能はない
