# Day 05（12/5 土）衛星画像で森の変化を検知

- **アプリ名（フォルダ名）**：`forest-change-detector`
- **ジャンル**：宇宙
- **完成形**：Webアプリ＋Pythonのデータ処理
- **組み合わせるデータ**：Global Forest Watch（森林減少の地図・国ごとの数字・原因・火災）× Natural Earth × ウェブ検索（＋ロンドニア州の分析で Sentinel-2・OpenStreetMap）
- **AI・技術の見どころ**：植生指数＋画像の説明

## 作るもの

地球全体で、2001〜2025年に森が減った場所を年ごとにたどる地図。地域（6大陸＋ロシア）ごとに、毎年どれだけ減ったか、そのうち火災がどれだけかを数字とグラフで示し、大きく減った年に何があったかを、AI がウェブ検索で調べて出典つきで説明する

（当初の仕様は「地域を選ぶと、2つの時期の衛星画像から植物の量の変化を計算し、変化した場所とその理由の候補をAIが説明する」。ロンドニア州の1か所で作ったが、「1か所だけでなく地球全体を年ごとに見たい」という要望で、画面は地球全体に作り直した。ロンドニア州の分析は `scripts/` と `analysis/` に残してある。2026-11-23）

## 使い道

森林減少のニュースを、地球全体の中で位置づけて理解する。地理空間データ・オープンデータを扱う開発の入門

## どんな効果があるか

- **地球のどこで、いつ森が減ったかが一目で分かる**：再生ボタンを押すと、2001年から1年ずつ、森が減った場所が地図に広がっていく。アマゾンの南の縁（「森林破壊の弧」）、東南アジアの農園の開発、カナダやロシアの山火事、北欧の林業などが、年ごとに現れる
- **地域ごとの規模と変化が数字で分かる**：2001〜2025年に世界で 5億4,281万 ha の森が減った。いちばん多いのは北アメリカ（1億3,330万 ha）で、半分近くは火災による。ロシアは7割、オセアニアは5割が火災。アフリカは火災が2%で、ほとんどが焼畑と農地への転換
- **「なぜその年に増えたのか」が分かる**：2023年の北アメリカ（カナダの記録的な山火事）、2024年の南アメリカ（干ばつと火災）、2016年の南アメリカ（エルニーニョ）など、大きく増えた年に何があったかを、出典のリンクつきで読める

## 確かめ方（評価）

Global Forest Watchの森林減少データを正解として、検知した場所がどれだけ重なるかを測る（ロンドニア州の分析で実施。[eval/RESULTS.md](eval/RESULTS.md)）

地球全体の画面では、地域の数字の合計、AI の説明に出典が付いているか、文中の数字が集計か出典の文と一致するか、出典のリンクが実在するかを確かめた（[eval/EVENTS.md](eval/EVENTS.md)）

評価のスクリプトと結果は `eval/` に置く。

## 1日で作る工夫・注意

機械学習は使わず、植生指数（NDVI）の引き算で検知する。対象は1か所に絞り、画像は事前にダウンロードしておく（ロンドニア州の分析）。地球全体は、Global Forest Watch が集計済みのデータと地図タイルを使い、自分では集計し直さない

## 必要な環境変数

- 画面を見るだけなら：なし（データはすべてキー不要。AI の説明は事前に作ってある）
- 「その年に何があったか」を作り直すとき（`pnpm events`）：`ANTHROPIC_API_KEY`・`CLAUDE_MODEL`

## 使い方

### 画面

1. **地図**：▶ 再生を押すと、2001年から1年ずつ、森が減った場所が広がっていく。スライダーで好きな年に止められる。色は減った年（黄＝古い、赤＝新しい、明るいピンク＝選んだ年）、色の濃さは減った量。「その年だけ」にすると、その1年に減った場所だけになる。拡大すると30m単位まで見える
2. **選んだ年の数字**：地図の下に、その年に世界で減った面積と、地域ごとの横棒（オレンジ＝火災、青＝それ以外）、数字の表（減少・火災・前の年からの増え方・主な原因）が出る。地図の年を変えると一緒に変わる
3. **地域ごとの推移**：7つの地域の、2001〜2025年の棒グラフ（全部同じ目盛り）。棒にマウスを乗せると数字、押すとその年に移る。● はその地域の「最も多かった年」「前の年から最も増えた年」
4. **その年に何があったか**：14の年（7地域 × 2）について、コードが集計した数字と、AI がウェブ検索で調べた説明、出典のリンク。「地図を○年にする」で地図がその年になる

### 使用例

- **北アメリカ 2023年**：減少 1,056 万 ha（前の年の2.2倍）、77%が山火事。カナダが 857 万 ha。AI の説明では、カナダの記録的な山火事（異常な高温と少雨）。出典は WRI の分析など
- **南アメリカ 2024年**：757 万 ha（+63%）、火災 49%。干ばつと火災がブラジルやボリビアで広がった年
- **オセアニア 2019〜2020年**：オーストラリア南東部の大規模な山火事。2019年は前の年の約4倍
- **ロシア 2021年**：652 万 ha、82%が火災。サハ共和国（ヤクーチア）の大規模な山火事

## 実装メモ

### 方針の変更（2026-11-23）

1. 当初はロンドニア州の約20km四方を衛星画像（Sentinel-2）で分析した（下の「ロンドニア州の分析」）
2. 「1か所だけでなく、地球全体でタイムラインで見たい」という要望で、地球全体の地図（Global Forest Watch の地図タイル）を足した
3. さらに「大陸ごとにどれくらい減っているかを数字で」「どの年に何があってこんなに減ったのか」という要望で、地域ごとの数字と、その年の説明を足し、ロンドニア州の表示を画面から外した（スクリプトと評価はリポジトリに残す）

### 地球全体の地図・地域ごとの数字・その年の説明で分かったこと（2026-11-23）

- **地球全体の地図は、Global Forest Watch の地図タイルをブラウザで塗り直して作った**（1か所だけでなく地球全体を年ごとに見たい、という要望で追加）
  - タイル：`https://tiles.globalforestwatch.org/umd_tree_cover_loss/v1.13/dynamic/{z}/{x}/{y}.png`。キー不要（タイルのサービスの仕様書 OpenAPI にも認証の指定がない）。どのサイトからでも読め（`access-control-allow-origin: *`）、ブラウザに1年キャッシュされる
  - **サーバー側の `start_year` / `end_year` は効かない**：年を変えても、まったく同じ画像（同じハッシュ）が返った。代わりに画素の色に情報が入っている（青＝減少した年 − 2000、赤＝濃さ、不透明度＝減少の有無）。ブラウザで画素を読み、選んだ年までの減少だけを年ごとの色で塗り直す（GFW の公式サイトと同じやり方）。青が0の画素（年が入っていない）は表示しない
  - タイルは512pxで、256pxのタイルと同じ z/x/y の範囲を表す。Leaflet の 512px の格子では、表示の縮尺 Z のタイルが 256px の Z−1 の範囲になるので、Z−1 のタイルを取る
  - **最初は位置がずれていた**（試してもらって分かった）：自作の GridLayer に `zoomOffset: -1` を渡していたが、これは TileLayer 専用の設定で、GridLayer では無視される。1段違う縮尺のタイルを違う場所に描いていた。createTile の中で縮尺を自分で1つ下げて直した
  - **アメリカ大陸だけ、年を変えても色がそのまま残った**（試してもらって分かった）：塗り直すために覚えておくタイルの画素を、座標（z/x/y）をキーにして持っていた。地図は横に繰り返して表示される（アメリカ大陸が左右に2つ見えるなど）が、その2枚は同じ座標になるので、後の1枚が前の1枚を上書きし、前の1枚は読み込んだときの年（2025年）の色のまま塗り直されなかった。タイルの canvas そのものをキーにして直した。データ側を疑って、米国南東部の年の分布を縮尺ごとに調べたが、どの縮尺でも2001年は約5%で、データの問題ではなかった
  - **最初はほとんどの陸地に色がついていた**（同上）：濃さ（赤の値）が小さくても不透明度を最低35%にしていたため。低い縮尺では1画素が数km四方で、25年間に少しでも減った所はすべて色がつく（アマゾンのタイルで画素の44%、濃さの中央値は15）。不透明度を濃さの平方根にし、濃さ3未満は表示しないようにした（同じタイルで、表示は32%、はっきり見えるのは12%）
  - Global Forest Watch は Global Nature Watch に名前が変わっていた。利用規約には「API へのリクエストにはアカウントの API キーを付ける」とあるが、タイルのサービスにはキーを渡す仕組みがなく、タイルがこの API に含まれるかは規約から読み取れなかった。データは CC BY 4.0。規約が示す表示ルール（Resource Watch）に従い「powered by Resource Watch」を地図に表示した
  - 最初に調べたとき、バージョンの一覧を文字列の順で並べて最後を取ったら「v1.9.1」になり、タイルが 422 を返した（正しい最新は v1.13）

- **国ごとの数字もキーなしで取れた**：GFW の Data API は、query（キーが必要）とは別に download/csv（キー不要）があり、SQL で集計して CSV で取れる。`gadm__tcl__iso_change`（最新 v20260424、2025年まで）には、減少面積のほかに、火災による減少、原生林かどうか、原因（WRI・Google の推定）、CO2 の排出量まで入っていた。国×年で集計して約20秒
- **大陸の対応**：Natural Earth の CONTINENT を使った。フランスの海外の地域（フランス領ギアナなど）や係争地（カシミールなど）は国コードがないので、手で振り分けた（最初は16の地域が漏れていた）。**ロシアは別にした**：ふつうはヨーロッパだが、森の大半はシベリアにあり、世界で最も森が減っている国（25年で9,210万 ha、7割が火災）なので、ヨーロッパに入れると実態とずれる
- **新しいウェブ検索（`web_search_20260209`）では出典が付かなかった**：結果を裏でコードで絞り込む仕組みのため、文章に出典（citations）が付かず、出典を本文に書き込むだけだった。出典の URL と引用した文を照合に使いたいので、基本の版（`web_search_20250305`）に変えた
- **数字の照合で見つかったこと**：
  - AI が自分で倍率を計算していた（「約2.2倍」）→ 倍率もコードで計算して渡し、「自分で計算しない」と指示した
  - 英語の出典の「1.13 million hectares」を日本語に直すときに、AI が「076万ha」という崩れた数字を書いた → 照合で見つかった。「出典の書き方のまま書く」と指示した
  - 「2万6,669km²」のような万をはさむ書き方を、照合側が2つの数と読んでいた → 共通部品（packages/ai）を直した
  - 日付（「2019年12月」「2019〜20年」）の数字は照合から外した
  - 最終的に14件中12件で、文中の数字がすべて集計か出典の文と一致。残り2件（「約100年で3番目」「約30%」）は、出典の付いた文の外にある数字で、画面に ⚠ で示す
- **AI は、検索で確かめられないことを書かなかった**：ロシアの2016年やヨーロッパの2016年は、「その年だけを扱った記事は見つからなかった」と書いた
- 「その年に何があったか」の作成は、1回目は約2分、2回目は検索が遅く約25分かかった（料金はどちらも約0.6ドル）

### ロンドニア州の分析（画面からは外した。`scripts/pipeline.py` などと `analysis/rondonia/` に残す）

#### 試してわかったこと（2026-11-23）

- **キーなしで作れる**：仕様では Copernicus のアカウントと Global Forest Watch の API キーを使う予定だったが、どちらも要らない
  - **Sentinel-2 の画像**：AWS のオープンデータ（Element 84 の Earth Search。STAC という検索の仕組みで、雲の量や日付で探せる）。Cloud Optimized GeoTIFF なので、必要な範囲だけを読める。例：ブラジル・ロンドニア州の2024年7〜8月で、雲が10%未満の画像が19枚
  - **森林減少の正解**：Hansen らの Global Forest Change（メリーランド大学。Global Forest Watch の「森林減少」の元データ。CC BY 4.0）。Google Cloud Storage の公開タイルから取れる。最新は **GFC-2025-v1.13**（2025年までの減少）
- OpenStreetMap（道路・川・地名・土地利用）は Overpass API から取る（キー不要）

#### 実装してわかったこと（2026-11-23）

- **2024年はアマゾンの記録的な干ばつと火災の年で、前の年の画像の森が「森らしくなかった」**：2024年9月の画像では、Hansen で森とされる所の NDVI の中央値が 0.66 しかなかった（例年は0.8前後と考えていた）。最初に決めた「NDVI 0.7 以上が森」では森の大半を見落とし、検知はわずか193 ha、再現率は8%だった
  - 森の境目を、画像ごとに**大津の方法**（NDVI の分布を2つの山に分ける）で決めるようにした（0.386）
  - 変化していない森の NDVI は、2025年のほうが高かった（森全体で0.16上がっていた）。前の年に森だった所の変化の中央値を「年ごとのずれ」として差し引くようにした
  - しきい値（NDVI の下がり方 0.25）は評価の前に決めたまま。答え（Hansen）を見て選び直してはいない
- **答えの「年」と画像の日付が合わない**：Hansen は暦年（1〜12月）で数えるが、この地域で森が切られるのは乾季（8〜10月）が多く、10月の後は雨季で雲の少ない画像がない（2025年10月5日〜2026年2月に、雲20%未満の画像は0枚）。後の年は使える最後の 2025-10-04 にした
- **場所の選び方**：Hansen の2025年の減少が多い20km四方を、データから探した。いちばん多かったのはロンドニア州のすぐ北のアマゾナス州ラブレア（約4,100 ha）で、ロンドニア州の中ではポルト・ヴェーリョ市の南西部（約2,450 ha）。仕様どおりロンドニア州を選んだ
- **Hansen のファイルは1行ずつの帯で保存されている**（タイル状でない）ので、必要な範囲だけを読むのに向かない。森林減少の年（55MB）は丸ごと取得し、2000年の樹冠（205MB）は必要な範囲だけ HTTP で読んだ
- **衛星画像の読み込みが遅い**：必要な範囲を緯度経度の格子に直しながら HTTP で読むので、2枚で約9分。1回取ったら `data/scenes/` に保存して使い回す
- **大津の方法の書き間違い**：境目に「下のグループの最後のビンの中心」を返していて、そのビンの値が反対側に入ることがあった。テストで見つけて「上の端」に直した（結果への影響は 0.384 → 0.386 と小さかった）
- **OpenStreetMap には、この地域の農道・林道がほとんど登録されていない**（範囲の中で道路4本・川1本）。AI には「近くに道路がない」と書かせず、「地図に登録された道路からは遠い」と書くよう指示した
- **公開の Overpass API が 502 を返した**：間をあけて3回まで試すようにした（1回目のやり直しで成功）
- **雲の除去（SCL）の効果はほとんどなかった**：2枚とも範囲の中の99%以上が晴れていたため。雲の多い画像では効くはず
- **AI の答えは実行ごとに少し変わる**：同じ場所でも、迷う場所（#9）は2回の実行で候補の順番が入れ替わった。「候補」として表示している

#### 作るもの（当初の完成形）

- **Web アプリ**（静的なページ。Vercel）：対象の地域の地図に、前の年と後の年の衛星画像（トゥルーカラー）、植物の量（NDVI）の変化、検知した場所を重ねて表示する。スライダーで前後を比べる。検知した場所をクリックすると、AI による「理由の候補」と、その場所の数字（面積・NDVI の変化）が出る
- **Python のデータ処理**（事前に1回）：画像の取得 → NDVI → 変化の検知 → 場所ごとの数字 → AI の説明 → 画面用のファイル（画像のタイル・GeoJSON）
- 計算も AI の説明も事前に済ませるので、公開デモで AI を呼ばない（回数の上限も料金もかからない）

#### 処理の流れ

```
（事前・Python）
Earth Search で、同じ季節（乾季）の雲の少ない画像を2枚探す（前の年・後の年）
  │ ① 赤（B04）と近赤外（B08）を、対象の範囲だけ読む（10m）。雲や影の画素は SCL（シーン分類）で除く
  │ ② NDVI ＝（近赤外 − 赤）÷（近赤外 ＋ 赤）。植物が多いほど 1 に近い
  │ ③ 前の年は森（NDVI が高い）で、後の年に NDVI が大きく下がった画素を「変化」とする（しきい値はコードで決める）
  │ ④ 小さすぎる点（ノイズ）は除き、まとまり（連結成分）ごとに面積・NDVI の変化・形を計算
  ▼
  │ ⑤ 各まとまりの周りの OpenStreetMap（道路からの距離、川、土地利用）を調べる
  │ ⑥ Claude：まとまりの前後のトゥルーカラー画像（小さな切り抜き）と、④⑤の数字を見て、変化の理由の候補を書く
  │    （例：牧草地への転換、道路沿いの伐採、火災、川の流れの変化、雲や季節による見かけの変化）。数字はコードの値だけ
  ▼
  ⑦ 画面用のファイル（前後の画像、NDVI の変化の画像、まとまりの GeoJSON、説明）を書き出す

（Web）地図に重ねて表示。スライダーで前後を比べる
```

#### 評価の結果（2026-11-23）

詳細は [eval/RESULTS.md](eval/RESULTS.md)。正解（Hansen の2025年の減少）は範囲の中で 2,246 ha。Hansen の30mの画素ごとに比べた。

| 決まり | 検知した面積 | 適合率 | 再現率 | F1 |
| --- | --- | --- | --- | --- |
| 最初の決まり（森 NDVI≥0.7 固定、ずれを除かない） | 193 ha | 90.9% | 7.9% | 0.15 |
| **このアプリ（大津の方法＋年ごとのずれを除く）** | 1,207 ha | 63.1% | 34.1% | **0.44** |

- 検知したのに答えになかった場所のうち 27% は、Hansen では「2024年の減少」だった（前の年の画像 2024-09-24 の後、2024年中に切られた可能性）
- しきい値を 0.10〜0.40 で変えると、F1 は 0.34〜0.47（適合率と再現率の引き換え）

#### 評価（確かめ方）

- 正解：Hansen の森林減少（`lossyear`）のうち、**後の年に減少した**30mの画素。対象の範囲で、前の年の時点で森だった（`treecover2000` が高く、それまでに減少していない）ところ
- 指標：検知した画素と正解の重なり（適合率・再現率・F1）。解像度が違う（Sentinel-2 は10m、Hansen は30m）ので、30mにそろえて比べる
- 比較：しきい値を変えたときの適合率と再現率の関係。雲の除去（SCL）の有無でどれだけ変わるか
- 限界：Hansen は1年単位で、雲などで見落としもある。森の「劣化」（一部の木を切る）は NDVI ではとらえにくい


## 記事を書くときのメモ

Qiita の記事を書くための材料。下書きは [ARTICLE.md](ARTICLE.md) にもある。

### 一言でいうと

地球全体で2001〜2025年に森が減った場所を年ごとに再生する地図に、地域ごとの数字と「その年に何があったか」を足した。数字は Global Forest Watch の公開データ（キー不要）を集計し、説明は AI がウェブ検索で出典を確かめて書く。数字は集計か出典の文と自動で照合する。最初は1か所の衛星画像の分析として作り、試してもらいながら地球全体に作り直した。

### AI の振る舞いで面白かった例

- 北アメリカ 2023年：「原因の77%は山火事で、増加の中心はカナダです…世界資源研究所（WRI）などの分析では、カナダの減少の90%超が火災によるもの」と、集計の数字と出典の数字を分けて書いた
- ロシア 2016年・ヨーロッパ 2016年：「その年だけを扱った記事は見つからなかった」と正直に書いた
- 英語の出典の「1.13 million hectares」を日本語に直すときに「076万ha」と崩れた数字を書き、照合で見つかった（出典の書き方のまま書くよう指示して直った）
- 自分で倍率（「約2.2倍」）を計算した → コードで計算して渡すようにした

### ハマったところ（記事向けの言い方）

1. GFW の地図タイルに年を指定しても、同じ画像が返ってくる（年は画素の青に入っていた）
2. 地図の位置がずれた（Leaflet の GridLayer では zoomOffset が効かない）
3. アメリカ大陸だけ、年を変えても色が変わらなかった（地図の繰り返し表示で、同じ座標のタイルが上書きし合っていた）
4. 少しでも減った所がすべて濃く塗られ、陸地がほとんど色で埋まった
5. 新しいウェブ検索の機能では、文章に出典が付かなかった
6. 1か所の分析（ロンドニア州）では、2024年の干ばつで「森の判定」が通用しなかった（再現率8% → 34%）

### 正直に書いておくこと（限界）

- 森の「減少」だけで、植林や自然の回復で増えた分は差し引いていない
- 地域の数字は国ごとの集計の合計。国の中の地域差（例：アマゾンと南部）は地図で見るしかない
- 「その年に何があったか」の年はコードが機械的に選んだもの（最も多かった年・最も増えた年）で、その地域で最も重要な出来事とは限らない
- 数字の照合は「同じ数字があるか」まで。文の意味や、出典がその文を本当に支えているかは確かめていない
- 背景の地図の上の色は、Global Forest Watch のタイルの読み方を推測して作った（年＝青、濃さ＝赤）。公式の資料では確かめられなかった
