# Day 05（12/5 土）衛星画像で森の変化を検知

- **アプリ名（フォルダ名）**：`forest-change-detector`
- **ジャンル**：宇宙
- **完成形**：Webアプリ＋Pythonのデータ処理
- **組み合わせるデータ**：Sentinel-2 × Global Forest Watch × OpenStreetMap
- **AI・技術の見どころ**：植生指数＋画像の説明

## 作るもの

地域を選ぶと、2つの時期の衛星画像から植物の量の変化を計算し、変化した場所とその理由の候補をAIが説明する

## 使い道

環境調査や、地理空間データを扱う開発の入門

## どんな効果があるか

- **地球全体で、どこの森がいつ減ったかを年ごとにたどれる**：2001〜2025年の森林減少（メリーランド大学のデータ）を地図に重ね、再生ボタンで年ごとに広がっていく様子を見せる。アマゾンの道路沿いの「魚の骨」状の切り開き、東南アジアの農園の開発、北米・北欧の林業の伐採などが、拡大すると30m単位まで見える
- **アマゾンで森が切り開かれていく様子を、自分の目で確かめられる**：ブラジル・ロンドニア州の約20km四方で、2024年9月と2025年10月の衛星画像を並べ、森が減った約1,200 ha（東京ドーム約260個分）の場所を地図に示す。スライダーで前後を比べ、場所を押すと理由の候補が出る
- **機械学習なしでも、半分以上は当たる**：植物の量（NDVI）の引き算だけで、検知した場所の約6割が、メリーランド大学の森林減少データでも2025年に減少していた
- **衛星データを扱う開発の入門になる**：キー不要のオープンデータ（Sentinel-2・Hansen・OpenStreetMap）だけで、取得・計算・答え合わせまでの一通りが動く

## 確かめ方（評価）

Global Forest Watchの森林減少データを正解として、検知した場所がどれだけ重なるかを測る

評価のスクリプトと結果は `eval/` に置く。

## 1日で作る工夫・注意

機械学習は使わず、植生指数（NDVI）の引き算で検知する。対象は1か所に絞り、画像は事前にダウンロードしておく

## 必要な環境変数

- データ：なし（Sentinel-2 は AWS のオープンデータ、森林減少は Hansen の公開タイル、地図は OpenStreetMap。2026-11-23 確認）
- AI の説明（事前に作るとき）：`ANTHROPIC_API_KEY`・`CLAUDE_MODEL`

## 使い方

### 画面

**上：地球全体の地図（2001〜2025年）**

1. 再生ボタン（▶ 再生）を押すと、2001年から1年ずつ、森が減った場所が広がっていく。スライダーで好きな年に止められる
2. 色は減った年（黄＝古い、赤＝新しい、明るいピンク＝選んだ年）。「その年だけ」にすると、その1年に減った場所だけになる
3. 拡大すると30m単位まで見える。青い四角（ロンドニア州）を押すと、下の詳しい分析に移る

**下：ロンドニア州の約20km四方を衛星画像で確かめる**

1. 地図に、対象の範囲の衛星画像（後の年）と、森が減ったと検知した場所（赤）が出る
2. 上のスライダーを左に動かすと前の年（2024-09-24）、右で後の年（2025-10-04）の画像になる。見比べると、森（濃い緑）が四角く切り開かれた所が分かる
3. 黄色い丸（AI の説明つき）か赤い丸を押すと、右にその場所の前後の画像の切り抜き、NDVI の変化、地図に登録された道路までの距離、AI による理由の候補が出る
4. 下の一覧から選んでもよい。「計算のしかたと、どれくらい当たったか」に、方法と答え合わせの結果がある

### 使用例

- **#1（153 ha）**：前の年は森と一部の切り開き。後の年には四角い区画状に森が失われ、茶色い裸地と明るい緑の草地に。AI の候補は「牧草地・農地への転換（高い）」「火災（中くらい）」「道路沿いの伐採（低い）」
- 上位12か所のほとんどで、AI は「牧草地・農地への転換」を第一の候補に挙げた。森を切って燃やし、牛の牧草地にする、この地域で典型的な流れと合っている

## 実装メモ

### 試してわかったこと（2026-11-23）

- **キーなしで作れる**：仕様では Copernicus のアカウントと Global Forest Watch の API キーを使う予定だったが、どちらも要らない
  - **Sentinel-2 の画像**：AWS のオープンデータ（Element 84 の Earth Search。STAC という検索の仕組みで、雲の量や日付で探せる）。Cloud Optimized GeoTIFF なので、必要な範囲だけを読める。例：ブラジル・ロンドニア州の2024年7〜8月で、雲が10%未満の画像が19枚
  - **森林減少の正解**：Hansen らの Global Forest Change（メリーランド大学。Global Forest Watch の「森林減少」の元データ。CC BY 4.0）。Google Cloud Storage の公開タイルから取れる。最新は **GFC-2025-v1.13**（2025年までの減少）
- OpenStreetMap（道路・川・地名・土地利用）は Overpass API から取る（キー不要）

### 実装してわかったこと（2026-11-23）

- **地球全体の地図は、Global Forest Watch の地図タイルをブラウザで塗り直して作った**（1か所だけでなく地球全体を年ごとに見たい、という要望で追加）
  - タイル：`https://tiles.globalforestwatch.org/umd_tree_cover_loss/v1.13/dynamic/{z}/{x}/{y}.png`。キー不要（タイルのサービスの仕様書 OpenAPI にも認証の指定がない）。どのサイトからでも読め（`access-control-allow-origin: *`）、ブラウザに1年キャッシュされる
  - **サーバー側の `start_year` / `end_year` は効かない**：年を変えても、まったく同じ画像（同じハッシュ）が返った。代わりに画素の色に情報が入っている（青＝減少した年 − 2000、赤＝濃さ、不透明度＝減少の有無）。ブラウザで画素を読み、選んだ年までの減少だけを年ごとの色で塗り直す（GFW の公式サイトと同じやり方）。青が0の画素（年が入っていない）は表示しない
  - タイルは512pxで、256pxのタイルと同じ z/x/y の範囲を表すので、Leaflet では `tileSize: 512, zoomOffset: -1`
  - Global Forest Watch は Global Nature Watch に名前が変わっていた。利用規約には「API へのリクエストにはアカウントの API キーを付ける」とあるが、タイルのサービスにはキーを渡す仕組みがなく、タイルがこの API に含まれるかは規約から読み取れなかった。データは CC BY 4.0。規約が示す表示ルール（Resource Watch）に従い「powered by Resource Watch」を地図に表示した
  - 最初に調べたとき、バージョンの一覧を文字列の順で並べて最後を取ったら「v1.9.1」になり、タイルが 422 を返した（正しい最新は v1.13）

- **2024年はアマゾンの記録的な干ばつと火災の年で、前の年の画像の森が「森らしくなかった」**：2024年9月の画像では、Hansen で森とされる所の NDVI の中央値が 0.66 しかなかった（例年は0.8前後と考えていた）。最初に決めた「NDVI 0.7 以上が森」では森の大半を見落とし、検知はわずか193 ha、再現率は8%だった
  - 森の境目を、画像ごとに**大津の方法**（NDVI の分布を2つの山に分ける）で決めるようにした（0.386）
  - 変化していない森の NDVI は、2025年のほうが高かった（森全体で0.16上がっていた）。前の年に森だった所の変化の中央値を「年ごとのずれ」として差し引くようにした
  - しきい値（NDVI の下がり方 0.25）は評価の前に決めたまま。答え（Hansen）を見て選び直してはいない
- **答えの「年」と画像の日付が合わない**：Hansen は暦年（1〜12月）で数えるが、この地域で森が切られるのは乾季（8〜10月）が多く、10月の後は雨季で雲の少ない画像がない（2025年10月5日〜2026年2月に、雲20%未満の画像は0枚）。後の年は使える最後の 2025-10-04 にした
- **場所の選び方**：Hansen の2025年の減少が多い20km四方を、データから探した。いちばん多かったのはロンドニア州のすぐ北のアマゾナス州ラブレア（約4,100 ha）で、ロンドニア州の中ではポルト・ヴェーリョ市の南西部（約2,450 ha）。仕様どおりロンドニア州を選んだ
- **Hansen のファイルは1行ずつの帯で保存されている**（タイル状でない）ので、必要な範囲だけを読むのに向かない。森林減少の年（55MB）は丸ごと取得し、2000年の樹冠（205MB）は必要な範囲だけ HTTP で読んだ
- **衛星画像の読み込みが遅い**：必要な範囲を緯度経度の格子に直しながら HTTP で読むので、2枚で約9分。1回取ったら `data/scenes/` に保存して使い回す
- **大津の方法の書き間違い**：境目に「下のグループの最後のビンの中心」を返していて、そのビンの値が反対側に入ることがあった。テストで見つけて「上の端」に直した（結果への影響は 0.384 → 0.386 と小さかった）
- **OpenStreetMap には、この地域の農道・林道がほとんど登録されていない**（範囲の中で道路4本・川1本）。AI には「近くに道路がない」と書かせず、「地図に登録された道路からは遠い」と書くよう指示した
- **公開の Overpass API が 502 を返した**：間をあけて3回まで試すようにした（1回目のやり直しで成功）
- **雲の除去（SCL）の効果はほとんどなかった**：2枚とも範囲の中の99%以上が晴れていたため。雲の多い画像では効くはず
- **AI の答えは実行ごとに少し変わる**：同じ場所でも、迷う場所（#9）は2回の実行で候補の順番が入れ替わった。「候補」として表示している

### 作るもの（完成形）

- **Web アプリ**（静的なページ。Vercel）：対象の地域の地図に、前の年と後の年の衛星画像（トゥルーカラー）、植物の量（NDVI）の変化、検知した場所を重ねて表示する。スライダーで前後を比べる。検知した場所をクリックすると、AI による「理由の候補」と、その場所の数字（面積・NDVI の変化）が出る
- **Python のデータ処理**（事前に1回）：画像の取得 → NDVI → 変化の検知 → 場所ごとの数字 → AI の説明 → 画面用のファイル（画像のタイル・GeoJSON）
- 計算も AI の説明も事前に済ませるので、公開デモで AI を呼ばない（回数の上限も料金もかからない）

### 処理の流れ

```
（事前・Python）
Earth Search で、同じ季節（乾季）の雲の少ない画像を2枚探す（前の年・後の年）
  │ ① 赤（B04）と近赤外（B08）を、対象の範囲だけ読む（10m）。雲や影の画素は SCL（シーン分類）で除く
  │ ② NDVI ＝（近赤外 − 赤）÷（近赤外 ＋ 赤）。植物が多いほど 1 に近い
  │ ③ 前の年は森（NDVI が高い）で、後の年に NDVI が大きく下がった画素を「変化」とする（しきい値はコードで決める）
  │ ④ 小さすぎる点（ノイズ）は除き、まとまり（連結成分）ごとに面積・NDVI の変化・形を計算
  ▼
  │ ⑤ 各まとまりの周りの OpenStreetMap（道路からの距離、川、土地利用）を調べる
  │ ⑥ Claude：まとまりの前後のトゥルーカラー画像（小さな切り抜き）と、④⑤の数字を見て、変化の理由の候補を書く
  │    （例：牧草地への転換、道路沿いの伐採、火災、川の流れの変化、雲や季節による見かけの変化）。数字はコードの値だけ
  ▼
  ⑦ 画面用のファイル（前後の画像、NDVI の変化の画像、まとまりの GeoJSON、説明）を書き出す

（Web）地図に重ねて表示。スライダーで前後を比べる
```

### 評価の結果（2026-11-23）

詳細は [eval/RESULTS.md](eval/RESULTS.md)。正解（Hansen の2025年の減少）は範囲の中で 2,246 ha。Hansen の30mの画素ごとに比べた。

| 決まり | 検知した面積 | 適合率 | 再現率 | F1 |
| --- | --- | --- | --- | --- |
| 最初の決まり（森 NDVI≥0.7 固定、ずれを除かない） | 193 ha | 90.9% | 7.9% | 0.15 |
| **このアプリ（大津の方法＋年ごとのずれを除く）** | 1,207 ha | 63.1% | 34.1% | **0.44** |

- 検知したのに答えになかった場所のうち 27% は、Hansen では「2024年の減少」だった（前の年の画像 2024-09-24 の後、2024年中に切られた可能性）
- しきい値を 0.10〜0.40 で変えると、F1 は 0.34〜0.47（適合率と再現率の引き換え）

### 評価（確かめ方）

- 正解：Hansen の森林減少（`lossyear`）のうち、**後の年に減少した**30mの画素。対象の範囲で、前の年の時点で森だった（`treecover2000` が高く、それまでに減少していない）ところ
- 指標：検知した画素と正解の重なり（適合率・再現率・F1）。解像度が違う（Sentinel-2 は10m、Hansen は30m）ので、30mにそろえて比べる
- 比較：しきい値を変えたときの適合率と再現率の関係。雲の除去（SCL）の有無でどれだけ変わるか
- 限界：Hansen は1年単位で、雲などで見落としもある。森の「劣化」（一部の木を切る）は NDVI ではとらえにくい

### 一言でいうと

キー不要のオープンデータ（Sentinel-2・Hansen・OpenStreetMap）だけで、アマゾンの森が減った場所を NDVI の引き算で見つけ、メリーランド大学の森林減少データで答え合わせし、AI に理由の候補を挙げさせた。2024年の記録的な干ばつのせいで「決まった値で森を判定する」素直なやり方は8%しか見つけられず、画像ごとに境目を決め、年ごとのずれを除くことで34%まで上がった。

### AI の振る舞いで面白かった例

- #1（153 ha）：「前の年にすでに一部が切り開かれていた区画の周辺で、後の年には四角い区画状に森が広く失われ、茶色い裸地や明るい緑の草地が広がったと考えられる」。候補は牧草地への転換（高い）・火災（中くらい）・道路沿いの伐採（低い）
- 道路の距離が遠いとき、「画像には線状の道が見えるが、地図に登録された道路までは 2.6km あり、道沿いの伐採と断定する根拠は弱い」と、画像と地図のずれを自分で指摘した
- 迷う場所（#9）では、2回の実行で候補の順番が入れ替わった

### ハマったところ（記事向けの言い方）

0. 地球全体の地図：GFW のタイルの「年」の指定がサーバーでは効かず、画素の青の値に年が入っていた。ブラウザで読み取って塗り直した
1. 2024年の記録的な干ばつで、前の年の森の NDVI が低く、「NDVI 0.7 以上が森」が通用しなかった（再現率8%）
2. 変化していない森が翌年のほうが緑だったので、単純な引き算では見落とす
3. 答えのデータは暦年、森が切られるのは乾季の後半、その後は雨季で画像がない
4. Hansen のファイルがタイル状でなく1行ずつの帯で、必要な範囲だけを読むのに向かない
5. 大津の方法の境目を1ビン分ずらして返していた（テストで発見）
6. OpenStreetMap にアマゾンの農道がほとんど載っていない

### 正直に書いておくこと（限界）

- 対象は1か所・1年だけ
- 答え（Hansen）も衛星から作ったデータで、見落としや誤りがある
- 画像の日付と答えの年がずれる（再現率と適合率の両方を下げる）
- NDVI は植物の量なので、木の一部だけを切る「劣化」や、切った後すぐ草が生えた所はとらえにくい
- AI の理由は画像と数字からの推測で、現地で確かめたものではない。実行ごとに少し変わる
