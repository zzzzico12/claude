# Day 01（12/1 火）論文サーベイの自動化

- **アプリ名（フォルダ名）**：`paper-survey`
- **ジャンル**：論文
- **完成形**：Webアプリ＋API
- **組み合わせるデータ**：OpenAlex × arXiv × Unpaywall
- **AI・技術の見どころ**：RAG・要約

## 作るもの

テーマを入れると、重要論文、無料で読めるリンク、日本語の要約をまとめたサーベイを出す

## 使い道

新しい技術を調べるときの最初の1時間を短くする

## 確かめ方（評価）

既存のサーベイ論文の参考文献を正解として、何割を拾えたか（再現率）を測る

評価のスクリプトと結果は `eval/` に置く。

## 実装メモ

### 試してわかったこと（2026-11-22）

- **引用数の順に並べると、テーマに関係の薄い有名論文が上に来る。** 「retrieval augmented generation」を引用数順で検索すると、上位は GPT-3・GPT-4・SciPy だった。**関連度（`relevance_score`）で候補を集めてから、コードで引用数と新しさを加味して並べ直す**方式にする
- 関連度順に `publication_year` で絞ると、上位はほぼすべてテーマどおりの論文になる
- **同じ論文が2件出ることがある**（arXiv版と学会版など。例：RAGの原論文が2件）。タイトルを正規化して1件にまとめ、引用数は多いほうを使う
- **Unpaywall は Crossref の DOI だけが対象**で、arXiv の DOI（`10.48550/...`）は 404 になる。arXiv の論文は OpenAlex の `open_access.oa_url` と arXiv のリンクを使い、Unpaywall は雑誌・学会の論文に使う
- 既存のサーベイ論文の参考文献は、OpenAlex の `referenced_works` で取れる（例：RAGのサーベイ W4389984066 は158件）→ 評価の正解に使える

### 実装してわかったこと（2026-11-22）

- **抄録の代わりに書誌情報が入っている論文がある**（例：Active RAG は「著者名＋会議名」だけの211文字）。AI が要約できないので、300文字未満の抄録は候補から外した
- **年が後から出た雑誌版の年になることがある**（例：CRAG は2024年1月の arXiv 論文だが、OpenAlex では2026年）。arXiv の番号（`2401.15884` → 2024年1月）から年を出し、早いほうを使う
- **数字の照合で誤検出が出た**：抄録の「45 million」を AI が「4,500万」と正しく直したのに、照合側が英語の million を読めなかった → `packages/ai` の数字の読み取りを million / billion / 7B などに対応させた
- **AI は抄録にないことを補わなかった**：抄録が書誌情報だけの論文について「抄録からは内容を確認できない」と書いた。関係の薄い論文（RAG のテーマに画像生成の GLIGEN が混ざった）も「RAG そのものを扱っていない」と指摘した
- **評価の締め切り日**：雑誌版の公開日を使うと、サーベイが引用しようのない新しい論文まで候補に入る。arXiv の第1版の日付を使うようにした
- 1回のサーベイ：約40秒、本文 約6,700字、根拠の番号 約100か所

### データの利用条件と無料枠（2026-11-23 確認）

- **OpenAlex**：「Every record is released under a CC0 public-domain license」（[help.openalex.org/access/pricing](https://help.openalex.org/access/pricing)）。商用・非商用の制限なし
- **Unpaywall**：「In late 2025 we moved Unpaywall onto the OpenAlex database」「We are not retiring Unpaywall」（[help.openalex.org/access/unpaywall](https://help.openalex.org/access/unpaywall)）。同じデータベースなので CC0 として扱う
  - Unpaywall 公式サイト（利用規約・API の説明）は JavaScript で表示する作りで、プログラムからは読めなかった。Unpaywall API 固有の回数制限（よく引かれる「1日10万回」）は公式の記述を確認できていない。このアプリの利用は最大でも1日200回（20本×10回）なので、問題にならない
- **OpenAlex の無料枠**：キーありで1日1ドル分（UTC 0時にリセット）。**検索は1,000回で1ドル**、ID での取得は無料（[help.openalex.org/access/example-costs](https://help.openalex.org/access/example-costs)）
  - このアプリ：サーベイ1回で検索4回 → 上限の1日10回でも40回。評価（`pnpm eval --fresh`）は検索25回ほど＋参考文献の取得（一覧取得は1万回で1ドル）。無料枠で十分足りる

### 処理の流れ

```
テーマ（日本語）
  │ ① Claude：英語の検索語を2〜4個に言い換える（generateObject、effort: low）
  ▼
OpenAlex 検索（検索語ごとに関連度順で上位100件、抄録ありに絞る）
  │ ② コード：重複をまとめ、点数で並べ直して上位20本を選ぶ
  │    点数 = 関連度の順位 + log(1年あたりの引用数) + 新しさ（期間はUIで選べる。既定は直近10年）
  ▼
上位20本 ─③ 無料で読めるリンク：OpenAlex の oa_url → Unpaywall（Crossref DOIのみ）→ arXiv
  │ ④ Claude：抄録だけを根拠に、日本語のサーベイを書く
  │    ・1本ごとに2〜3文の要約、全体を3〜5個の流れに分けた解説
  │    ・文には根拠の論文番号 [3] を付けさせる
  ▼
  ⑤ コード：照合
     ・[n] がすべて実在する20本を指しているか
     ・文中の数字（年・引用数）が元データと合うか（packages/ai の checkNumbers）
  ▼
画面：サーベイ本文＋論文の一覧（タイトル、年、引用数、無料リンク、要約）＋出典
```

- **数字はコードが出す**：引用数・年・本数は一覧の表に出す。Claude には「数字を書かず、表を参照させる」よう指示し、それでも書かれた数字は照合する
- **抄録の扱い**：OpenAlex の抄録は単語の位置の形式（`abstract_inverted_index`）なので、コードで文章に戻す。抄録のない論文は候補から外す
- **抄録は1回の呼び出しにまとめて渡す**：20本 × 約300トークン。Sonnet 5.5 で1回あたり約0.05〜0.08ドル（約10円）の見込み

### 構成

- `src/`：画面（Vite + TypeScript、Reactなし）
- `api/survey.ts`：Vercel Function。OpenAlex・Unpaywall・Claude をサーバー側で呼ぶ（キーとメールアドレスをブラウザに出さない）。サーベイ本文はストリーミングで少しずつ返す
- `lib/`：検索・並べ替え・照合の処理。画面のAPIと評価スクリプトの両方から使う
- `scripts/`、`eval/`：評価

### 評価（確かめ方）

- **正解**：既存のサーベイ論文5本の参考文献（`referenced_works`）
- **条件をそろえる**：検索をサーベイの公開日より前の論文に限り、サーベイ自身は除く。テーマには、サーベイのタイトルを人が短く言い換えた日本語を使う
- **指標**：上位20本と、並べ替え前の候補100本のそれぞれで、何割が参考文献に入っていたか（再現率）と、上位20本のうち何本が参考文献か（適合率）
- **比較**：「キーワードで検索し、引用数の順に並べただけ」の方式と比べる
- 参考文献は100〜200本あるので、20本で拾えるのは一部になる。重要論文を拾えているかを見る指標として、記事に限界も書く

### 公開デモの料金対策

- 同じテーマの結果はキャッシュして、Claude を再度呼ばない（キャッシュから返すときは回数に数えない）
- **1日の上限は全体で10回**（2026-11-22 決定。Sonnet 5.5 で1回約10円 → 1日最大約100円）。1人で使い切らないよう、IPごとに1日3回まで
- 回数とキャッシュの保存先：**Upstash Redis**（2026-11-22 決定）。手元の開発ではメモリに置く。`lib/store.ts` は Upstash の環境変数（`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`、または `KV_REST_API_URL` / `KV_REST_API_TOKEN`）があれば自動でそちらを使う

### デプロイ（Vercel）

- 公開URL：https://advent26-paper-survey.vercel.app （Vercel のプロジェクト名 `advent26-paper-survey`）
- Vercel で `zzzzico12/claude` を Import し、**Root Directory を `advent-2026/paper-survey`** にする。ほかの設定（インストール・ビルド・関数の実行時間）は `vercel.json` に書いてある
- 環境変数：`ANTHROPIC_API_KEY`・`CLAUDE_MODEL`・`OPENALEX_API_KEY`・`CONTACT_EMAIL`
- Storage（Marketplace）から Upstash Redis を追加してプロジェクトにつなぐ（環境変数は自動で入る）
- このフォルダか `packages/` に変更がないコミットでは、ビルドしない（`ignoreCommand`）。環境変数だけ変えて Redeploy するときは「Use project's Ignore Build Step」のチェックを外す
- 2026-11-23 本番で確認：サーベイ1件 38秒・根拠の番号108か所すべて実在・照合できない数字0。同じテーマの2回目はキャッシュから0秒で返った

### AI の振る舞いで面白かった例

- **抄録にないことを書かなかった**：抄録が「著者名＋会議名」だけの論文について、「抄録からは内容を確認できない」と書いた（その後、そういう論文は候補から外した）
- **関係ない論文を自分で指摘した**：RAG のテーマに画像生成の GLIGEN が混ざったとき、「[18] は画像生成の論文で、RAG そのものを扱っていない」と書いた
- **頼んでいない数字を足した**：共通部品の動作確認で「地球から月まで384,400km」だけを渡したら、「光なら約1.3秒」を自分で足した。値はおおむね正しいが、元データにない数字なので照合で検出された。「数字はコードで出す」ルールを入れた理由として使える

### ハマったところ（記事向けの言い方）

1. 引用数順に並べると、テーマと関係の薄い有名論文が上に来る
2. 同じ論文が arXiv 版と学会版で2件出る
3. 年が後から出た雑誌版の年になる（2024年1月の arXiv 論文が2026年に）→ arXiv の番号 `2401.xxxxx` から年を出す
4. 抄録の代わりに書誌情報だけが入っている論文がある → 300文字未満は除外
5. Unpaywall は arXiv の DOI を知らない（404）
6. 評価の締め切り日を雑誌版の日付にすると、サーベイが引用しようのない論文まで候補に入り、評価が不公平になる → arXiv 第1版の日付にした
7. 数字の照合で、英語の「45 million」を読めずに誤検出した → 共通部品を直した

### 正直に書いておくこと（限界）

- サーベイの参考文献は150〜350本あるので、20本で拾える割合（再現率）は5%前後。主な指標は適合率にした
- 参考文献に入っていない論文が、関係のない論文とは限らない
- 参考文献の一覧は改訂後の最終版のもので、第1版より後の論文も含まれる（どの方式にも同じように効くので、比較には影響しない）
- 検索語は Claude が作るので、実行するたびに結果が少し変わる
- 評価は5本だけ。重みは最初に決めた値のままで、評価に合わせた調整はしていない（調整すると評価用データに合わせ込むだけになる）
- 解説は抄録だけが根拠なので、論文本文の内容までは反映されない

### スクリーンショットの候補

- テーマを入れて、解説が少しずつ表示されている途中
- 右側の「自動チェック」（すべて ✓）
- 本文の `[3]` を押して、表の3行目が強調された状態
- 選んだ論文の表（引用数・無料で読むリンク・点数。点数にマウスを乗せると内訳が出る）

### 次にやりたいこと（候補。人が選ぶ）

- 抄録だけでなく、無料で読める論文の本文（PDF）も根拠にする
- 評価のサーベイを増やし、AI 以外の分野（医学、材料など）でも測る
- 結果を Markdown や BibTeX でダウンロードできるようにする
